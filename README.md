# 冷链交接采录台

离线导入交接扫描与温度日志，保留输入哈希、事件、问题和逐箱判定。所有样本是合成数据。

## 启动与测试

在仓库目录运行 `python -m coldhandoff demo`，打印报告路径；`python -m coldhandoff --help` 查看子命令；`python -m pytest -q` 运行测试。仅依赖 Python 3.11+ 标准库，测试需要 pytest。

## 数据流

来源文件 → 原始事件 → 设备序列与校时检查 → 箱号状态与封签检查 → 温度区间计算 → 决策 → JSON 证据报告。`batch` 一对多 `box`，`source_file` 一对多 `raw_event`；事件和问题指向来源，决策指向箱。事件不可覆盖，来源哈希用于幂等。缺口、未知箱号或冲突保留为问题，不能视作正常。

## 状态与规则

交接顺序为 dispatch → arrival → sign；open 与 reseal 必须配对。温度样本间隔不超过 30 分钟，必须覆盖运输区间；连续超阈值达到批次定义的分钟数判异常。结果为完整、异常、证据不足。规则版本保存在决策行。当前时间校准只检查锚点偏移漂移，尚未据此重算事件时间；未实现人工复核写回。

安装检查：在仓库目录运行 `python -m pip install . --no-build-isolation`；本地开发也可直接运行模块命令。报告同时生成 JSON 和 Markdown，`inspect` 子命令可追踪单个对象。

审计台账：Run 由规则版本和来源摘要确定，Evidence 关联原始对象与来源，Decision 引用 Run；重复核验保持同一输入的报告稳定。

原始来源字节迁移前保存在 SQLite BLOB 中，JSON 证据包以 Base64 表示字节；修改输入文件不会覆盖已采录证据。

## 内容寻址归档（在线迁移）

原始来源可无损迁移到内容寻址块仓（数据库旁的 `cas-objects/`），在保留逐字节可复原审计能力的同时消除相似文件的重复占用。

- **不可改写块仓**：块按 SHA-256 命名（`xx/<hash>`），临时文件 + 原子改名写入；相同字节在磁盘上只存一份，对象一经发布不再修改。
- **两种无损表示**：`fixed_64` 按 64 字节固定边界切块；`record_chunks` 把每条 JSONL 记录连同其原始分隔字节（`\n`/`\r\n`）作为块，并单独记录 BOM/前导空行与无末尾换行状态。两者都按 manifest 顺序拼回**原始逐字节内容**，重新得到原 `source_file.hash`；不重新序列化 JSONL。
- **manifest 与世代**：每个来源的 manifest 不可变，重发布追加新世代；指针切换用来源版本/世代的原子比较交换。读者在打开时钉住一个已发布世代（`cas_pin`），读取期间视图稳定。
- **并存与安全回收**：迁移期间旧 BLOB 与新 manifest 可并存；仅当重建 SHA-256 与原 BLOB 完全一致才切换指针、随后回收冗余 BLOB。GC 只删除当前指针、活跃读者可见 manifest 与宽限期内清单均不引用的块；迁移持共享文件锁、GC/恢复持排他锁，杜绝回收与注入竞态。
- **崩溃恢复**：分块写一半、未发布、已切换未回收等故障都可在重启后幂等继续；恢复保证每个已切换来源至少有一份完整且哈希校验通过的副本。

相关命令：`archive --representation {fixed_64,record_chunks}` 执行迁移并输出清单/校验/存储账证据；`verify-archive` 逐源重建校验；`storage-account` 区分物理唯一块数与逻辑引用数（不把逻辑去重误报为磁盘节省）；`gc` 与 `recover` 执行安全回收与崩溃恢复；`report` 始终经由统一读路径（迁移前读 BLOB、迁移后按 manifest 重组），Base64 证据保持逐字节稳定。所有数据均为本地虚构样本。
