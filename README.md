# 冷链交接采录台

离线导入交接扫描与温度日志，保留输入哈希、事件、问题和逐箱判定。所有样本是合成数据。

## 启动与测试

在仓库目录运行 `python -m coldhandoff demo`，打印报告路径；`python -m coldhandoff --help` 查看子命令；`python -m pytest -q` 运行测试。仅依赖 Python 3.11+ 标准库，测试需要 pytest。

## 数据流

来源文件 → 原始事件 → 设备序列与校时检查 → 箱号状态与封签检查 → 温度区间计算 → 决策 → JSON 证据报告。`batch` 一对多 `box`，`source_file` 一对多 `raw_event`；事件和问题指向来源，决策指向箱。事件不可覆盖，来源哈希用于幂等。缺口、未知箱号或冲突保留为问题，不能视作正常。

## 状态与规则

交接顺序为 dispatch → arrival → sign；open 与 reseal 必须配对。温度样本间隔不超过 30 分钟，必须覆盖运输区间；连续超阈值达到批次定义的分钟数判异常。结果为完整、异常、证据不足。规则版本保存在决策行。当前时间校准只检查锚点偏移漂移，尚未据此重算事件时间；未实现人工复核写回。

安装检查：在仓库目录运行 `python -m pip install . --no-build-isolation`；本地开发也可直接运行模块命令。报告同时生成 JSON 和 Markdown，`inspect` 子命令可追踪单个对象。

审计台账：Run 由规则版本和来源摘要确定，Evidence 关联原始对象与来源，Decision 引用 Run；重复核验保持同一输入的报告稳定。

原始来源字节保存在 SQLite BLOB 中，JSON 证据包以 Base64 表示字节；修改输入文件不会覆盖已采录证据。

## 离线承运费率采集与报价主数据

在真实到仓扫描（box-A）与四份冻结来源（A 承运商两页 HTML、B 承运商 CSV、A 已签补充价 JSON）之上，构建「页面 SHA/分页 → 字段抽取 → 服务身份归并 → 区间费率图 → 候选主数据版本 → 发布回执 → 客户报价」的因果链。该流水线不决定箱装哪辆车、不读箱温度 decision、不核销银行款项。

费率流水线命令（`--db` 复用同一 SQLite 库）：

1. `tariff-register`：冻结真实到仓事件、来源 SHA 与 HTML/CSV/JSON 原字节。
2. `tariff-build --authority {public_tariff,signed_addendum}`：抽取并整版校验，生成确定性版本 ID。
3. `tariff-publish`：整版推送到模拟报价端点（`mock-rate-master`），仅在 ACK 后成为现行版本；`--partial-services`、`--lose-ack` 用于故障注入。
4. `tariff-quote`：只读取已 ACK 的现行版本 ID 报价，绝不临时抓网页重算。
5. `tariff-report --out`：输出费率图、版本差额、报价的 JSON/Markdown。

归并与隔离规则：

- 身份键为承运商 + 服务身份 + 储温 + 有效期 + 计费重量区间。A 的 COLD24 与补充价别名 ICE24 仅在签署别名与 2–8°C 储温同时核验后归并；A 的 ROOM24（15–25°C）始终单列；B 的 FROZEN-24 是另一承运商服务，不因名称相似并入 A。
- 重量区间为半开 `[min,max)`，同重量/服务只允许命中一条合法价格；重叠、断档、重复修订、跨页冲突价、分页缺页/环、跨页修订不一致、补充价签署/有效期异常都保留两来源并隔离为 issue，阻断发布，不做「末行覆盖」或最低价静默裁决。
- 附加费保留整数分精度（燃油按基价百分比半入整分）。计费重量取实重与体积重（5000 cm³/kg）的较大者：box-A 实重 4kg、体积重 6kg，故命中 5–10kg 区间而非首屏 0–5kg。

两条事先授权的报价权威互不混用：`public_tariff` 发布 A 冷藏 6kg 850 分、B 750 分，最低选 B；`signed_addendum` 核验补充价后以排他条款替换 A 对应级距为 500 分、B 仍 750 分，最低选 A。室温服务在两版中均单列。

版本栅栏与审计：新版本整版校验通过才可发布；部分服务推送、ACK 丢失、并发发布工人、晚到旧页或半抓取都不会让旧现行价失效或产生半版收费（`BEGIN IMMEDIATE` + 现行行唯一语义 + 旧行 `superseded` 退役留痕）。更正已生效价格只发新版本并写差额审计（`tariff_audit`），旧报价行永久引用其历史版本 ID，不改写历史。原箱扫描、温度结论与来源字节均原样保留。

测试运行 `python -B -m pytest -q -p no:cacheprovider`，覆盖分页缺页、跨页修订、别名冲突、房温/冷藏误合并、体积重级距、两权威路线、部分发布/迟到旧页/并发与旧报价保持。
